# 6단계 — 대전 엔진 + 공격형 교사 + 랭킹 학습 (2026-09-16)

> 계획 개편: 6단계 = 이 문서, 7단계 = 커넥톰 배선 제약 + 가중치 학습, 8단계 = 웹(대전 UI; 1차 시각화 콘솔은 `docs/stage8-web-v1.md`), 9단계 = 보고서.
> **주장 변경**: 7단계 이후 커넥톰에서 오는 것은 **배선 구조뿐이고 가중치는 학습된다.** 정확한 표현은 "초파리 커넥톰 배선 제약을 가진 네트워크" 다.
> 5단계까지의 음성 결과(`docs/stage5-separation.md`)는 보고서의 근거 장으로 그대로 둔다.

데이터: `data/teacher-attack.json` (튜닝된 교사 + 평가), `data/versus-decisions.json.gz` (40,000 결정), `data/rank-train.json` (검증 실행).
재현: `npm test` → `npm run tune-teacher` → `npm run collect-versus` → `npm run rank-train` → `npm run estimate-budget`.

## 0. 왜 이 단계인가

5단계의 결론은 "고정 리저버 + 회귀 리드아웃은 결정 내 순위를 담지 못한다" (결정 내 τ 0.058, 플레이 무작위 수준) 였다. 진단된 원인은 둘이다:

1. **손실 함수 오설계** — afterstate 단위 회귀 손실은 결정 간 분산(보드 채움)에 지배되어 결정 내 순위가 학습 신호에 들어가지 않았다.
   풀링 R² 0.817 vs 결정 내 τ 0.058 이 그 증거다.
2. **고정 가중치의 표현력 한계** — 7단계에서 커넥톰을 희소성 마스크로 바꾸고 가중치를 학습한다.

6단계는 (a) 사람과 대전할 수 있는 엔진, (b) 가비지를 보내는 교사, (c) 결정 단위 랭킹 손실 파이프라인을 만들고, 5단계 동작점의
고정 리저버에 손실만 바꿔 **원인 1 의 크기**를 잰다. 여기서 좋은 성능이 안 나와도 정상이다 — 억지로 맞추지 않았다.

## 1. 대전 엔진 (`src/tetris.js` 아래 절반)

2단계 배치 단위 API(하드드롭만, 40 행동)는 그대로 두고 그 아래에 순수 함수로 덧붙였다. 상태 변이 금지 — 모든 함수가 새 객체를 돌려준다.

- **hold** 1칸, 배치당 1회 (`holdSwap` 은 `holdUsed` 면 throw, `placePiece` 가 푼다). 빈 hold 로 교환하면 next[0] 이 현재 조각이 되고 큐가 한 칸 나간다.
- **next 5** 노출. 7-bag 은 순수 함수 `pieceSequence(seed).at(k)` (`createBag` 과 같은 순서 — 테스트).
- **가비지**: 큐 `[{ lines, hole }]` FIFO. 한 번의 공격은 같은 구멍 열. 조각 확정 직후, 그 배치가 줄을 지우지 않았을 때 하단 삽입, 한 번에 최대 8줄(잔여는 큐에).
  위로 밀린 블록이 보드를 벗어나면 **탑아웃**. `boardHeight`, `columnHeights` 노출.
- **공격** (가이드라인, B2B 는 구현하지 않음): 줄 1/2/3/4 → 0/1/2/4, T-스핀 1/2/3 → 2/4/6, 콤보 표 (1–2 +0, 3–4 +1, 5–6 +2, 7–10 +3, 11+ +4; 첫 클리어 = 콤보 1),
  퍼펙트 클리어 +10. **상쇄**: 보낼 라인 < 받을 큐면 큐 앞에서 차감하고 0 을 보낸다 (잔여만 수신); 보낼 라인 ≥ 큐면 큐를 비우고 차액을 보낸다.
- **T-스핀** = T 조각 + 마지막 동작이 회전 + T 박스 3×3 네 모서리 중 3개 이상 채움(벽·바닥 포함). 앞쪽 두 모서리가 모두 채움이거나 5번째 킥(TST) 이면 full, 아니면 mini
  (mini 는 일반 줄 공격으로 취급).
- **"마지막 동작이 회전" 판정** — 배치 단위 API 라 엔진이 판정한다. 처음엔 "수직 낙하 후 회전 한 번"(spin finish) 으로 구현했는데 이 모델에서는 **T-스핀 트리플이 나올 수 없다**
  (TST 는 오버행 아래로 수평 이동이 필요하다 — 브루트포스 2^15 배치 중 0). 그래서 **스폰 위치에서 가이드라인 이동(좌·우·소프트드롭·SRS 킥 회전)으로 도달 가능한 정지 위치 전체를
  BFS** 로 구하는 `reachablePlacements` 로 바꿨다. 각 정지 위치에 `spin`(회전으로 도달하는 경로 있음), `drop`(이동으로 도달), `kick5` 플래그가 붙는다.
  같은 결과 셀 집합은 하나로 합친다 (O 의 4 회전, S/Z/I 의 2 회전). 보드 위 2행 버퍼에서 스폰·이동하고, 버퍼에 걸쳐 고정되는 위치(lock out)는 후보에서 뺀다.
  스카이라인 위 빈 영역은 자유 이동이 가능하므로 (rot, 열) 마다 가장 낮은 빈 행을 시드로 넣어 그 아래만 탐색한다 — 조각당 20–35 µs.
- 검증 (`test/versus.test.js`): 손으로 만든 TSD 슬롯(오버행 한쪽) → full · 2줄 · 공격 4, 미러 동일; 양쪽 오버행은 도달 불가; 세로로 떨어진 T 는 3 모서리여도 mini;
  평평한 바닥의 T 는 null; TST 슬롯 → 5번째 킥 · 3줄 · 공격 6; 가비지 상쇄 3 사례; 상한 8줄; hold 재사용 금지; 콤보 표 + 연속 더블 5회의 공격 열; 퍼펙트 클리어; 오버행 아래 tuck; 순수 7-bag;
  상태 불변; 결정성.

## 2. 공격형 교사 (`src/teacher-attack.js`)

Dellacherie 는 생존 최적화라 1000조각 398줄을 전부 싱글·더블로 지운다 (공격 0 에 가깝다). 사람을 이기려면 가비지를 보내야 한다.

- **특징 11** = Dellacherie 6 + `attackSent`(상쇄 전 공격 라인), `comboState`(배치 후 콤보), `wellDepth`(우물 1열을 뺀 나머지 열의 최소 높이 − 우물 높이, 4 상한 = 테트리스 준비도),
  `tspinSetup`(0 / 1 T-슬롯 형태 / 2 TSD 준비), `garbageQueueHeight`(상쇄·삽입 뒤 남은 큐). 과도 특징 4개는 경로를 따라 누적, 상태 특징 7개는 leaf 보드.
- **위험 전환**: 결과 보드 높이 + 남은 큐 ≥ `dangerHeight` 인 노드는 Dellacherie 고정 가중치(생존)로 평가, 공격 항 0. `dangerHeight` 는 튜닝 파라미터.
- **빔 서치** next 5 + hold, 깊이 3 · 폭 8. 전치(두 조각의 순서만 바꾼 경로 = 같은 상태) 제거. 결정당 ~850 전이 평가, 3–6 ms.
  **scored 모드**(데이터 수집용): 첫 단계 후보 전체에 각각 폭 8 하위 빔을 돌려 후보마다 값을 매긴다 (25배 비쌈, ~70–200 ms/결정). 선택 = argmax.
- **CEM** (`scripts/tune-teacher.js`): 세대 20 × 개체 50, 상위 10% 로 평균·표준편차 갱신, 시드 고정, 세대 안 공통 난수. 목적함수 = 보낸 공격 라인 총합 + 0.5 × 생존 조각 수
  (개체당 2 게임, 상한 700). 초기 평균은 손으로 몇 점 찔러 테트리스가 나오는 영역으로 두었다 (Dellacherie 원 가중치는 우물을 벌점해 테트리스를 절대 쌓지 않는다).
- 1-ply 는 같은 가중치로도 테트리스를 거의 못 쌓는다 — `test/versus.test.js` 에서 빔 > 1-ply 공격을 확인.

## 3. 데이터 (`scripts/collect-versus.js`, `src/versus-data.js`)

결정 단위 기록: 상태(보드·가비지 큐·hold·next 5·콤보·받은 가비지 누계) + 후보 전체(hold 여부·col·rot·top·spin·kick5·교사 값·공격·줄·T-스핀·위험) + 교사 선택 + 실제 둔 후보.
결과 보드는 저장하지 않는다 — 엔진이 결정적이라 `applyDecision` 으로 정확히 복원된다 (역직렬화 검사: 후보 17,829 개 이벤트·다음 결정 보드 불일치 0).
방문 정책 교사 0.9 / 무작위 0.1, 인공 가비지 조각당 확률 0.08 로 1–4 줄 (분포 0.4/0.3/0.15/0.15), 게임당 최대 250 결정, 게임 단위 60/20/20 분할 + 누수 검사.

## 4. 랭킹 학습 (`src/rank-train.js`, `scripts/rank-train.js`)

배치의 단위가 afterstate 가 아니라 **결정**이다. 손실 4종: `mse`(5단계 회귀, afterstate 단위 평균) · `centered`(결정 내 중심화 회귀, 진단용) · `listwise`(softmax CE, 교사 선택 = 정답) ·
`pairwise`(힌지 m = 1). 모델 2종 linear / MLP(64). 입력 3종: `dn` 고정 리저버 DN 발화율 107 (5단계 C0 재캘리브레이션 점, T 25, G_IN×1.62 — R3:V2 리드아웃이 학습된 그 리저버) ·
`board` 원 보드 200 셀(리저버와 같은 정보 — 원인 2 통제) · `hand` 교사 특징 11 + 위험 플래그(참조). Adam, 미니배치 32 결정, 검증 손실 조기 종료.
평가는 테스트 결정의 결정 내 τ(점수 vs 교사 값) · top-1(argmax = 교사 선택) 이 주 지표, 풀링 R² 는 mse 만 보조. listwise 기울기는 수치 미분과 대조 (`test/rank-train.test.js`, 4 손실 × 2 모델).

결정 *간* 성분이 새어 들어온 것이다 — 줄을 많이 지운 후보의 결과 보드가 훨씬 비어 있어 전역 가치가 높게 나오는 효과이고, 그 오프셋을 빼면 사라진다.

같은 정보(원 보드 200 셀)에 같은 손실을 쓰면 τ 0.11–0.23, top-1 30–43% 가 나온다. 리저버가 받은 입력에는 순위 정보가 있는데 DN 발화 수 107 개에는 남지 않는다 —
**원인 2(고정 가중치의 표현력)가 지배적이고 원인 1 의 기여는 측정 한계 안에서 0 이다.** 랭킹 손실 자체는 정상 작동한다: 원 보드에서 listwise/pairwise 는 mse 보다 top-1 을
+12~14%p (CI 분리) 올린다 (mlp: mse 29.2% → listwise 41.4% / pairwise 43.4%). 합성 데이터 테스트(결정 간 오프셋이 큰 선형 교사)에서도 listwise 가 mse 를 압도한다.

#### listwise vs pairwise · mse 의 τ

- listwise 와 pairwise(힌지 m=1) 는 모든 입력·모델에서 CI 가 겹친다. top-1 은 pairwise 가 근소하게 높고 (board mlp 43.4 vs 41.4), τ 는 board 에서 pairwise 가 높다 (0.230 vs 0.202).
  힌지는 위반 쌍만 밀어 후보 전체의 순서를 조금 더 살리고, softmax CE 는 정답 하나에 집중한다 — 정성적으로 예상과 일치.
- **mse 는 표현이 좋으면 τ 가 가장 높다** (board mlp τ 0.312 vs listwise 0.202; hand 0.55 vs 0.46) 대신 top-1 이 낮다 (29% vs 41%). 회귀는 후보 전체의 값을 맞추고 랭킹 손실은
  1등을 맞춘다 — 목적이 top-1(어느 배치를 두느냐)이라면 랭킹 손실, 후보 전체 순서라면 회귀가 낫다. 5단계의 "회귀가 결정 내 순위를 못 담는다" 는 표현이 좋을 때는 성립하지 않는다.
- hand(교사 자신의 특징)조차 top-1 60% 다: 교사 값은 깊이 3 빔의 결과라 1-ply 특징의 함수가 아니다. 이 60% 가 이 데이터에서 "1-ply 리드아웃" 의 실질 상한이다.

### 5.4 7단계 예산 (`npm run estimate-budget`)

실측 단위 비용 (실제 CSR, 단일 스레드): 순전파(희소 matvec + tanh) 1.4 ms, 역전파(Wᵀδ + dW 누적) 5.6 ms → 언롤 스텝당 **7.0 ms** (15 ns/간선). 12 워커 병렬 배율 ×7.6 (실측).
계획(40,129 결정 × 42.5 후보, T 25, listwise BPTT, epoch 10): 학습 결정 하나 7.5 s(단일) → epoch 7.0 h → **기대 70 h, 상한(20 epoch) 141 h ≫ 8 h. 멈춤.**

| 축소 | 기대 | 상한 | 대가 |
|---|---|---|---|
| 후보 K 42.5 → 8 (교사 선택 + 상위 7) | 13.2 h | 26.5 h | 쉬운 음성 제거 — listwise 신호는 상위 후보 순위에 있다. 데이터 재수집 불필요 |
| K 8 + 결정 24k → 8k | **4.4 h** | 8.8 h | 상태 분포 덮임 감소 (6단계 rank-train 이 8k 결정으로 돌았으니 검증된 규모) |
| T 25 → 15 | 42 h | 84 h | 분리도 감소 (5단계: dnDiff 는 T 와 단조) |
| 간선 weight ≥ 5 (63% 간선 / 90% 시냅스) | 37 h | 74 h | 커넥톰 제약 자체를 바꿈 |
| K 8 + T 15 | 7.95 h | 15.9 h | |
| K 8 + T 15 + weight ≥ 5 | 4.2 h | 8.3 h | |

**권장**: (1) 학습 표본 — 결정당 후보를 교사 선택 + 상위 7 로 (시간은 K 에 선형, 커넥톰·동역학은 그대로) → 그래도 넘치므로 (2) 결정 수 24k → 8k (기대 4.4 h) 또는 T 25 → 15 (7.95 h, 상한이 넘친다).
간선 가지치기는 연구 대상(배선 제약)을 바꾸므로 마지막 수단으로만 — weight ≥ 5 는 시냅스의 90% 를 유지해 정당화할 여지가 있다.
LIF + 대체 기울기를 쓰면 ×1.5 (가정) 이라 같은 축소에서도 6.6 h 가 된다. 이 추정은 JS 단일 스레드 희소 연산 기준이다 — 역전파 5.6 ms 는 전치 순회의 캐시 미스가 지배하므로,
간선을 (post, pre) 로 정렬한 CSC 를 따로 두거나 dW 를 워커별로 나누면 2–3× 는 더 줄일 수 있다 (미실측).

## 6. 결론

1. **원인 1(손실 오설계)의 기여는 고정 리저버에서는 0 이다.** 같은 DN 특징에 mse / centered / listwise / pairwise 를 걸어도 결정 내 τ 0.00–0.03, top-1 16–20% 로 CI 가 전부 겹친다.
   랭킹 손실은 정상 작동한다 (원 보드 입력에서 top-1 +12–14%p, 합성 데이터에서 mse 압도) — 문제는 손실이 아니라 **DN 발화 수 107 개에 결정 내 순위 정보가 없다**는 것이다.
2. **원인 2(고정 가중치의 표현력)가 지배적이다.** 리저버가 받는 것과 같은 정보(원 보드 200 셀)를 그대로 리드아웃에 주면 τ 0.31 / top-1 43% 가 나온다. 이것이 7단계에서 가중치를
   풀었을 때 "같은 입력 정보로 얕은 리드아웃이 도달하는" 참조점이고, 교사 자신의 특징으로도 60% 가 상한이다 (교사 값이 깊이 3 빔의 결과라서).
3. 7단계 설계에 대한 함의: 기대 이득의 하한을 "손실 교정" 에서 잡을 수는 없다 (0). 이득은 전부 표현(가중치 학습)에서 와야 하고, 그 상한은 이 데이터에서 얕은 리드아웃 기준 top-1 40%대,
   교사 특징 기준 60% 다. 예산은 후보 8개 + 결정 8k (4.4 h) 로 줄여 시작하는 것이 맞다.
4. 대전 엔진·공격형 교사는 목표를 넘겼다 (공격 중앙값 377/1000, 생존 100%). 8단계 대전 UI 가 붙일 상대는 이 교사다.

## 7. 예상과 달랐던 점

- **T-스핀 트리플은 "낙하 후 회전" 모델로는 불가능**했다 (2^15 배치 브루트포스 0). 오버행 아래로의 수평 이동이 필요해 BFS 도달성으로 바꿨고, 그 덕에 tuck·spin 이 모두 정확한
  가이드라인 물리가 됐다. BFS 는 처음 0.2–0.45 ms 였는데 스카이라인 시드로 20–35 µs 가 됐다.
- **교사는 T-스핀을 버렸다.** CEM 이 `tspinSetup` 가중치를 음수로, `cumulativeWells` 를 양수로 보냈다 — 공격 + 0.5×생존 목적함수에서는 우물 하나로 테트리스를 연속으로 내는 것이
  모든 T-슬롯 빌드보다 낫다 (82% 의 줄이 테트리스). T-스핀은 가비지 구멍이 있을 때만 자주 나온다 (수집 중 440 회 vs 단독 플레이 게임당 1.4 회).
- **가비지를 받으면 공격이 늘었다** (377 → 418): 가비지 줄 상쇄가 공격에 포함되고, 구멍을 지우는 싱글·더블이 늘어 콤보가 붙는다.
- **mse 가 표현이 좋을 때는 τ 가 가장 높았다** (board mlp 0.31 vs listwise 0.20). "회귀가 순위를 못 담는다" 는 표현이 나쁠 때만 맞는 말이었다. 랭킹 손실의 이득은 τ 가 아니라 top-1 에 있다.
- **탐색 잡음 ε 0.1 + 가비지에서 게임의 57% 가 250 결정 전에 죽었다** — 교사 단독으로는 1000 조각 생존 100% 인데도. 무작위 배치 하나가 우물을 막으면 회복이 어렵다.
  데이터에 위기 상태가 많이 들어간 것은 대전 학습에는 오히려 좋다.
- 처음 수집 코드가 "살아남는 후보 없음" 종료를 `dead` 로 표시하지 않아 meta.deadGames 가 0 으로 찍혔다. 코드를 고치고 데이터 파일의 플래그만 보정했다 (결정 내용 무관, meta.note 에 기록).
- 5단계 참조값(τ 0.058)보다 6단계 dn 의 τ 가 낮다 (0.01–0.03). 교사가 달라졌기 때문이다 — Dellacherie 값은 1-ply 보드 함수라 리저버가 일부 담았지만, 깊이 3 빔 값은 결과 보드만으로는
  더 어렵다 (교사 특징 상한 60% 가 그 증거).

## 8. 소요
