# 4단계 — afterstate 학습 + null model 비교: 예산 추정에서 정지 (2026-09-15)

상태: **파이프라인 구현·검증 완료, 본 실험 미실행.** `npm run estimate-budget` 이 8시간 상한을 넘겨 (상한 39 h) 스펙대로 멈췄다.
축 결정 전에 알아야 할 진단 결과가 하나 더 있다 (§3): 현재 정식화에서 리저버는 같은 결정의 후보 afterstate 들을 구분하지 못한다.

## 3. 파이프라인 점검 실행(`--quick`, 24점 캘리브레이션·2 게임·상한 100)에서 나온 결과 — 결과가 아니라 진단

- ρ_unit: **alpha 1 은 모든 조건에서 0.9991–1.0000** (수신 가중치 합 정규화라 위상 불변 — 3단계 재파라미터화가 null 비교에서는
  아무것도 구분하지 않는다). **alpha 0.5 는 구분한다**: C0 59.2, C4 59.1, C5 59.2 vs C1 33.7, C2 34.0, C3 27.8 — 실제 커넥톰의
  허브-허브 구조가 스펙트럼 반경을 null 대비 ~2배 키운다. 이것이 지금까지 얻은 가장 명확한 "C0 는 null 밖" 신호다.
- 24점 탐색에서 C1s0, C3s0 은 통과점 0 ("동작 영역 없음" 후보; 300점에서 재확인 필요).
- 회귀: 풀링 R² 0.71–0.80 인데 **결정 내 켄달 τ 는 −0.06~+0.04, top-1 8–15%** (후보 수 ~32 이니 우연 ≈ 3–15%). C6(활동량 5개)도
  R² 0.71–0.76. 즉 풀링 R² 는 결정 간(보드 채움 정도) 분산이고, 결정 내 순위는 아무 조건·리드아웃도 못 맞춘다.
- 플레이: 전 조건·조합 pieces 중앙값 19–29, lines 0 (무작위 기준선 27 조각). 교사는 100 조각 상한에서 38.5 줄.

> **5단계 정정**: 아래 표는 테스트 분할의 *처음* 25개 결정(대부분 채움 ≤ 26셀인 초반 보드)에서 잰 것이라 대표성이 없다.
> 테스트 결정을 셔플해 50개로 재면 같은 동작점에서 서로 다른 DN 벡터 70%(동일 보드 중복 제거 후), 후보 쌍 간 DN 차이 30/107,
> 프로파일 736/1163/30 이다. 분리는 보드 채움에 따라 양극단이다 — 빈 보드(≤26셀)는 3–6%·0 DN, 찬 보드(≥48셀)는 50–100%·30–70 DN
> — 그리고 어느 쪽이든 결정 내 τ ≈ 0 이다. 자세히는 `docs/stage5-separation.md`.

**원인 진단** (C0, 테스트 분할의 처음 25개 결정 — 위 정정 참조):

| 측정 | 값 |
|---|---|
| 한 결정의 후보들이 만드는 서로 다른 DN 벡터 비율 | **7 %** (다른 표본: 22 %) — 34 후보가 2–8 벡터로 뭉침 |
| 두 후보 사이에 발화 수가 다른 DN 수 | **0.9 / 107** |
| 두 후보 사이 I_ext 가 다른 입력 뉴런 | 1,682 / 2,316 (최대 ΔI_ext 0.018 = G_IN 의 18 %) |
| 발화 수가 다른 입력 뉴런 | 52 / 2,316 |
| 발화 수가 다른 중간층 뉴런 | **0.6 / 5,577** |
| 창 200 ms 로 늘리면 | 입력 103, 중간 1.5, DN 0.6 — 여전히 없음 |

4셀 차이가 입력층 52 뉴런의 발화 수를 바꾸지만 중간층은 그 차이를 전파하지 않는다(0.6/5577). 리저버의 50 ms 응답은 공통 구동으로
결정되고, 후보 간 차이는 문턱 아래에서 사라진다. 인코더 쪽 조정(σ 2 → 0.7, 놓인 조각 셀 강조, 창 100 ms)을 40 결정으로 시험했더니
서로 다른 DN 벡터 22 → 35 %, 결정 내 중심화 릿지의 테스트 τ 0.08 → 0.12 — 의미 있는 순위 정보가 안 나온다.

## 4. 결정이 필요한 것

1. **축 축소** (스펙의 세 축 + 조합): §2 표. 조합 1–2 개로 줄이는 것이 가장 크다 (모든 조건에 동일 적용이라 비교는 유효).
2. **정식화**: §3 의 진단대로면 플레이 평가는 어떤 축으로 줄여도 전 조건이 무작위 수준으로 나온다. 선택지:
   (a) 그대로 실행해 "afterstate 표현이 결정 내 해상도를 갖지 못한다" 를 결과로 삼는다 (회귀만이면 1시간, 플레이까지 조합 1 이면 ~3시간).
   (b) 리드아웃 신호를 바꾼다 — DN 발화 수 대신/과 함께 창 끝 DN 막전위(연속값; 후보 쌍의 89/107 DN 에서 다르지만 크기는 작다),
       또는 더 큰 리드아웃 집단. DN 정체성이 전제인 프로젝트라 사용자 판단 사항.
   (c) 리저버가 입력 차이를 전파하는 동작점을 따로 찾는다 (하드 제약에 "후보 간 DN 분리" 항목 추가). 3단계 하드 제약 변경이라 사용자 판단 사항.

## 5. 스모크

`npm run smoke` 는 `data/results.json` 에 C0 학습 리드아웃이 있으면 afterstate 에이전트로 500조각을 돈다. quick 결과로 실행:
20.6 배치/s (배치당 25.7 후보 창, 530 창/s), 불법 배치 0, 에피소드 평균 23.8 조각. 3단계 랜덤 리드아웃 경로는 results.json 이 없을 때 유지된다.
